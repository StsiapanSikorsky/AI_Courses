# Векторные БД

## Общие сведения и принцип работы:
**Векторная БД (Vector Database)** - специальная система хранения и поиска предназначенная для работы с эмбеддингами. В отличие от традиционных БД (ищущих точное совпадение) векторные БД находят объекты семантически похожие друг на друга (на основе математического расстояния между векторами). Векторные БД ширко применяют для архитектуры *RAG (Retrieval-Augmented Generation)* позволяя LLM посмотреть базу знаний перед ответом

**Эмбеддинг** - способ преобразования реального объекта (слова, картинки, аудио) в набор чисел (математически вектор), который отображает смысл этого объекта и математически его описывает. По сути эмбеддинг это число координаты в векторном пространстве

**Семантический поиск** - метод поиска который пытается понять смысл и контекст запроса пользователя, работает на основе векторных представлений (эмбеддингов) и является практическим применением векторных БД

#### Принцип работы:
1) Запрос пользователя превращается в вектор
2) БД сравнивает его с сохраненными векторами (используя метрики сходства)
3) Возвращает объекты, чьи векторы оказались ближе всего

#### Метрики сходства (измерения расстояний между векторами):   
*1) Косинусное сходство (Cosine Similarity)* - измеряет косинус угла между векторами, игнорируя их длину. Идеально подходит для текста и LLM. Если документы имеют разный объем, но они об одном и том же, то косинуссное сходство покажет что они похожи   
*2) Евклидово расстояние (L2 Distance / Euclidean)* - измеряет прямое расстояние между точками в пространстве (как линейкой). Идеально подходит для картинок и аудио, где важна абсолютная точность совпадения признаков   
*3) Скалярное произведение (Dot Product/Inner Product/IP)* - измеряет длину проекции одного вектора на другой. Используется когда длина (модуль) эмбеддинга несет в себе полезную информацию, сохраняет как направление так и длину векторов   
4) Манхэттенское расстояние   
5) Расстояние Чебышёва   
6) Расстояние Минковского   
7) Расстояние Махаланобиса   
8) Коэффициент Жаккара   

#### Векторы можно хранить в:
1) В файле:
  - pickle - для быстрого сохранение Python объектов. Простотая и нативная для Python, небезопасно (выполняет код) и не переносится между языками
  - Parquet - для колоночного хранения больших наборов. Сжатие, аналитика, совместимо с pandas/Arrow. Нет встроенного ANN-индекса
  - feather 
  - ann (Annoy) - готовый индекс для поиска
  - voy (Voyager) - легкий ANN-индекс
  - Hdf5 - для научных данных и больших массивов
  - Safetensors - для безопасного хранения тензоров. Хорошая безопасность и скорость загрузки. Ориентирован на ML-модели а не на поиск
  - bin (для HNSWLib) - индекс HNSW
  - index (для FAISS) - индексы Facebook AI
  - npy
2) Расширения и настройки в БД:
  - pgvector и pgvectorscale
  - MongoDB Vector Search
  - Neo4j Vector Search
  - sqlite-vss / sqlite-vector
  - ClickHouse
3) Векторные БД
  - Milvus
  - ChromaDB
  - Qdrant
  - Weaviate
  - LanceDB
  - Turbopuffer
  - Pinecone
  - MyScale
  - Vespa

В файле можно хранить векторы когда: 
- нужно быстро собрать прототип и нет времени на развертывание сложныхсистем
- небольшое и статическое количество эмбеддингов (около 1000), меняются редко и обновляются под присмотром команды разработчика
- количество одновременно выгруженных эмбеддингов не перегружает RAM
- семантический поиск реализуется локально с помощью специальных библиотек (HNSWLib, FAISS, Annoy, Voyager)
